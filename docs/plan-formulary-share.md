# 規劃：院內清單標示＋分享查詢

- 修訂：v4（2026-11-13，經 Codex 規格覆審兩輪修訂，見文末修訂紀錄）
- 狀態：已實作。第一階段（SW＋頁面）PR #28；第二階段（manifest `share_target`）於正式站 SW 確認為 v12 後發布

## 目標

1. 查詢藥品時同時看到「是否為院內品項、院內代碼」
2. 可勾選「限院內」
3. Android 手機在其他 app 選字後，可分享到本站查詢國內與院內品項

使用者：維護者本人、Android、單次查詢。

## 不做

- 院內清單同步、雲端存放、多人發放、跨分頁即時同步
- oe-extension 的模糊比對與同成分／同 ATC 分類面板（本站已有 ATC 搜尋）
- iOS 專屬程式（只附捷徑說明）；檔案型分享
- `.xls`、加密檔、多工作表選取、ZIP64
- 防禦同 origin 其他專案頁讀取院內清單（見平台限制）

## 需求決策（已定案）

| # | 項目 | 決策 |
|---|---|---|
| Q1 | 比對鍵 | 主鍵健保代號、輔鍵許可證字號，**完整相等**比對。只有代碼對上才有「院內品項」徽章並納入「限院內」。逐列判定見「比對規則」 |
| Q2 | 失敗取向 | **寧可漏標徽章，不可讓「限院內」0 筆被讀成院內沒有** |
| Q3 | 清單時效 | 常駐顯示「匯入於 YYYY/MM/DD（N 天前）」。這是**本機匯入經過時間**，不代表院內藥檔的修訂日期，畫面文字不得寫成「清單更新日」。超過 `FORMULARY_STALE_DAYS = 90` 天改警示樣式，只警示不停用 |
| Q4 | 分享 | `share_target`（Android）＋ `#q=` 深連結（通用）。分享查詢用「全部」搜尋範圍（`data-scope="both"`），不自動改寫關鍵字 |

## 比對規則

### 清單列的處理順序

1. **原始資料列**：表頭之後的非空白列。表頭須在檔案**前 20 個非空白列**內
2. **排除列**（不保存，只計數）：① 無藥名（中文名與英文名皆空）② 院內碼重複（院內碼經 NFKC、去空白、轉大寫後相同者，保留檔案中**最先出現**的一列；空院內碼不參與去重，全部保留）
3. **品項**：其餘列。只保存六個欄位：`code`（院內碼）、`name`、`enName`、`ingredient`、`nhiCode`、`license`。**價格、儲位、ATC、藥理代碼等其他欄位不保存**

### 鍵的正規化

- 健保代號：NFKC、去除所有空白、轉大寫；結果須為 10 碼英數，否則視為空
- 許可證字號：NFKC、去除所有空白、去掉**末尾一個**「號」；與 `licenseNumber` 以同樣方式正規化後完整相等（v5：HIS 匯出常省略「號」，數字仍完整比對）
- 表頭沒有許可證欄時，以內容辨識：未對應到其他欄位、且過半數非空值形如「…字第＋數字（＋號）」的欄，取比例最高者；匯入狀態顯示採用的表頭與比例
- 不做前綴、子字串或去符號後的比對

### 品項分類（互斥，每個品項恰屬一類）

每個鍵先算出命中狀態：**0 張**（空、無效或站上找不到）／**1 張**（唯一一張許可證）／**多張**。對照表須保留「一鍵對多張」的事實，不可在建表時只留一張。依下列順序判定，先符合者為準：

| 順序 | 類別 | 條件 | 徽章 | 限院內 |
|---|---|---|---|---|
| 1 | K3 衝突 | 任一鍵為「多張」；或兩鍵皆為「1 張」但不是同一張 | 無（所有相關許可證皆不因此品項得到徽章） | 不納入 |
| 2 | K1 健保代號對應 | 健保代號為「1 張」（許可證鍵為「0 張」或同一張） | 該許可證卡片有徽章；健保代號表**該代號那一列**標院內碼 | 納入 |
| 3 | K2 僅許可證對應 | 許可證鍵為「1 張」、健保代號為「0 張」 | 該許可證卡片有徽章，註明「以許可證字號對應」並帶院內碼；健保代號表**不因此品項標任何列** | 納入 |
| 4 | K4 未對應 | 兩鍵皆為「0 張」 | 無 | 不納入 |

- 卡片徽章的院內碼＝該許可證所有 K1、K2 品項的院內碼集合；健保代號表各列只列**該代號的 K1 品項**院內碼。院內碼為空的品項仍使卡片顯示「院內品項」，只是不帶代碼
- 資料事實（2026-11-09 版）：站上 13,611 個健保代號皆為 10 碼英數、無一出現在兩張許可證上；K3 的「多張」分支目前不會觸發，仍須有測試釘住
- 匯入摘要顯示六個數字：K1／K2／K3／K4／無藥名／重複院內碼，**加總等於原始資料列數**

### 「限院內」

- 啟用條件：K1＋K2 ≥ 1。否則 disabled 並顯示原因（「尚未匯入」或「清單沒有任何可對應的健保代號或許可證字號」）
- 判定：卡片有至少一個 K1 或 K2 品項
- 套用順序：既有篩選範圍（`data-filter`）之後、劑型之前；ATC 子群點選照常作用
- 0 筆時顯示「院內清單中未對應到符合品項，不代表院內無此藥」與取消鈕；取消只取消這個勾選，其他條件（含 ATC 子群選取）不動
- 清單變更後若不再符合啟用條件，**自動取消勾選**再停用

### 名稱候選（卡片上的「可能為院內品項（名稱比對，未驗證）」）

- 只取 K3、K4 品項
- 條件：品項的 `name` 或 `enName`（NFKC、轉小寫、連續空白併為一個、去頭尾空白）與卡片的 `chName` 或 `enName` 同樣正規化後**完整相等**，且非空
- 不算徽章、不納入「限院內」

### 「院內清單有、但未對應到許可證」區塊

- 取 K3、K4 品項中，`name`／`enName`／`ingredient` 經 NFKC 轉小寫後**包含**關鍵字（同樣正規化）者；關鍵字少於 2 字不顯示
- 搜尋範圍為品名／成分／全部時皆以上述三欄比對；**ATC 範圍不顯示**
- **不受**篩選範圍、劑型、限院內影響，區塊內固定註明這一點
- 許可證卡片為 0 筆時仍顯示
- 最多列 20 筆，並顯示總筆數；K3 的列標示「代碼衝突」

## 架構決策與理由

| # | 決策 | 為什麼不選另一個 |
|---|---|---|
| D1 | 院內清單只存使用者瀏覽器，不進 repo、不上傳 | 本站是公開 GitHub Pages，無後端可做存取控制 |
| D2 | IndexedDB，資料庫名稱帶本站前綴 | `localStorage` 約 5 MB 上限且同步。前綴只為避免與同 origin 其他專案撞名或被誤刪，**不是存取隔離** |
| D3 | **整份清單存成單一筆紀錄**（`items`＋檔名＋匯入時間＋排除列計數），一次寫入 | 分成 items 與 meta 兩筆：可能只成功一半。單筆寫入由 IndexedDB 交易保證全有或全無 |
| D4 | **只持久保存清單本身**；對照索引、K1–K4 分類與摘要一律由「目前的 `drugs_data.json`＋目前的清單」在記憶體推導 | 把對應筆數存起來：站上資料每週更新，存的數字會與實際對照不一致 |
| D5 | 代碼完整相等比對決定徽章，不用名稱 | HIS 藥名多為簡稱，名稱比對會誤標 |
| D6 | 移植 `oe-extension/src/formulary.js` 的解析段成獨立 `formulary.js`（classic script），不引入套件、不併入 `app.js` | 本 repo 零依賴、`script-src 'self'`；純函式獨立檔可在 `node --test` 直接載入。代價：SW 預快取、CI 關卡、`package.json` 的 test 清單都要加檔 |
| D7 | 儲存層經一個薄介面存取（讀／寫／清除） | 測試需注入「寫入失敗」「讀取失敗」；直接呼叫 IndexedDB 則這些路徑無法在 `node --test` 驗證 |
| D8 | **`share_target` 用 POST**，`action` 為 `./share` | GET 會把分享文字放進網址；一旦 SW 不在（例如使用者清除網站資料但 PWA 仍安裝），文字就進 GitHub Pages 的請求紀錄，頁面端無法補救。POST 在同樣情況下文字只在請求本文，不進網址、歷史紀錄或 Referer |
| D9 | SW 攔下 `./share`，讀出文字後以 303 轉址到 `./#q=…`；**頁面只認 `#q=` 一個入口** | 兩個入口各自解析：容易出現行為不一致。fragment 不會送到伺服器 |
| D10 | `./share` 的任何請求 SW 都不發網路請求 | 該路徑在 GitHub Pages 上不存在，放行只會把分享內容送出去換一個 404 |
| D11 | 「限院內」為獨立勾選 | 併入單選篩選則「健保＋院內」「全部＋院內」無法表達 |
| D12 | 同一頁一次只進行一個清單操作：啟動讀取、匯入、清除任一進行中，上傳與清除皆停用，且程式層也拒絕第二個操作。其他分頁不即時同步，重新載入後生效 | 背景同步機制對單一使用者不值得；只靠 disabled 屬性擋不住已排入的操作 |
| D13 | `formulary.js` 載入失敗時，`app.js` 仍須正常運作，院內功能整個隱藏 | 新增檔案不可讓既有查詢失效 |

## 平台限制

- GitHub Pages：純靜態、無自訂 HTTP header；`liangrxdev.github.io` 由多個專案頁共用 origin，**同 origin 的其他專案頁程式碼讀得到本站的 IndexedDB**。這些專案都是維護者自己的，視為同一信任邊界
- CSP 為 `<meta>`（`script-src 'self'`、`connect-src 'self'`、`form-action 'none'`）。本次**不改 CSP**。`form-action` 管的是本頁送出的表單，不影響系統分享啟動的導覽，也不是防外洩機制
- Web Share Target：僅 Android Chromium 系、須安裝 PWA；`action` 以 manifest 所在位置解析，須落在 manifest scope 內。manifest 改動後已安裝的 WebAPK 更新有延遲
- 瀏覽器儲存：自動清除罕見，使用者手動清除網站資料較可能；安裝 PWA 不保證永久保存。對策只有「提示重新匯入」
- **隱私保證的範圍**：
  - 成立的部分：具備分享分支的 SW 生效時，分享文字不送往網路；頁面清理成功後，網址列與可返回的網址不含分享文字
  - **殘餘風險（接受）**：沒有「具備分享分支且已啟用的 SW」時——SW 不存在（清除網站資料後）、仍是舊版、新版安裝失敗——分享文字會以 POST 本文經 TLS 送到 GitHub Pages 並得到錯誤頁；瀏覽器是否把該 POST 本文留在本機工作階段歷史中屬瀏覽器行為，未驗證。具備分享分支的 SW 成功安裝並啟用後才恢復
  - 正常流程中，網址會短暫帶有 `#q=<文字>`，直到頁面清除為止；`app.js` 未載入或執行失敗時不會被清除
- **分兩次發布以消除「舊版 SW」過渡期**：第一次發布含 SW 分享分支與頁面 `#q=` 處理（manifest 不動）；確認正式站 SW 已是新版後，第二次才發布 manifest 的 `share_target`
- `drugs_data.json` 約 40 MB；對照索引在「站上資料載入完成」或「本頁清單變更」時各重建一次，不在每次搜尋重建

## 資料流

1. **匯入**：選檔 → 檢查大小（≤ 5 MB）→ 解析 → 檢查（有藥名欄、資料列 ≤ 20,000、至少一個品項）→ 寫入單筆紀錄 → **交易提交完成後**（IndexedDB 交易的 `complete`，不是單一 request 的 success）才更新畫面與對照。任何一步失敗：不寫入、整個可見狀態維持舊清單、顯示原因
2. **清除**：刪除紀錄 → 交易提交完成後才更新畫面；失敗則維持原狀並顯示原因
   - **清單變更成功後**：對照、摘要、目前搜尋結果的徽章、名稱候選、未對應區塊、限院內狀態，全部依新清單重算一次；關鍵字與其他篩選條件保留
3. **載入**：讀紀錄（無資料或讀取失敗 → 視為未匯入，後者另顯示提示）→ 站上資料載完後建對照
4. **查詢**：關鍵字 → 既有搜尋 → 篩選範圍 →（勾選時）限院內 → 劑型 → 排序 → 卡片；另算「未對應」區塊
5. **分享**：Android 分享 → POST `./share` → SW 讀 `text` 欄 → 303 到 `./#q=<編碼後文字>` → 頁面流程同 6
   - `text` 為空但 `url` 有值 → 303 到 `./#share=url`（頁面顯示「僅支援文字」）
   - 讀取失敗 → 303 到 `./#share=error`
   - SW 只做一件事：超過 500 個 Unicode 字元（code point）時取前 500 個，不可切斷代理對
   - `share_target`：`enctype` 為 `application/x-www-form-urlencoded`，`params` 為 `{ "title": "title", "text": "text", "url": "url" }`；SW 讀的欄名須與 manifest 一致
6. **深連結**：頁面載入或 `hashchange` 讀到 `#q=` → **立刻**以 `history.replaceState` 清掉 fragment（不等資料載入）→ 解碼 → 取第一個非空白行（以 CRLF／CR／LF 分行）、去頭尾空白 → 依長度決定是否搜尋

### 分享查詢的狀態規則

- 解碼失敗：不搜尋、不改搜尋框、顯示提示
- 長度以 Unicode 字元（code point）計。≤ 60：切到「全部」範圍並搜尋；> 60：整行填入搜尋框、不搜尋、顯示提示，**不截短**
- 空字串或只有空白：不搜尋，**保留**畫面上既有的搜尋框內容與結果
- 站上資料未載完：填入搜尋框並記為待執行；資料載完後執行**一次**
- 待執行只有一格：**任何**新收到的分享（含空白、超過 60 字、解碼失敗、`#share=url`／`#share=error`）都先取消舊的待執行項；使用者動了搜尋框即取消；資料載入失敗則丟棄（搜尋框文字保留）
- `#share=error`：不搜尋、顯示提示
- 0 筆且關鍵字含數字時，提示可只留藥名重查；**不自動重查**

## 支援的檔案格式

- `.csv`：UTF-8 或 Big5、逗號分隔、RFC 4180 引號
- `.xlsx`：只讀**第一個工作表**；公式儲存格取檔內已存的計算結果
- 其他（`.xls`、加密、損壞、ZIP64）：整份匯入失敗，保留舊清單；**不接受部分解析的結果**
- 上限：檔案 5 MB（含）、資料列 20,000（含）

## 驗收條件

自動測試一律用合成資料；真實院內藥檔**不進 repo、不進 fixture、不進測試輸出**。斷言一律以**許可證字號／健保代號識別特定卡片與特定列**，不可只驗「頁面某處出現某字串」。

### A 解析與匯入

- **A1** 同一份合成清單存成 UTF-8 CSV、Big5 CSV、XLSX，三者解析結果各自**等於事先寫定的預期品項陣列**（筆數、順序、六個欄位的值）。清單須含：中文、院內碼前導零、含逗號與引號的欄位、欄內換行、XLSX 的空儲存格。XLSX 另須：工作簿宣告的第一張工作表**不是** `sheet1.xml`，且另一張工作表放干擾資料；含一個帶已存結果的公式儲存格
- **A2** 表頭在第 20 個非空白列可解析；在第 21 個非空白列必須失敗。前面的列須包含一列非空白說明文字與一列空白列
- **A3** `ａｃ12345678`、` ac 12345678 ` 正規化後為 `AC12345678`；9 碼、11 碼、含 `-` 者為空。**反例**：站上有 `AC12345678` 時，清單寫 `AC1234567`（9 碼）或 `AC12345678X` 的品項不得讓任何卡片出現徽章
- **A4** 已有清單 X 時，下列每一種都必須：儲存層讀回仍等於 X、畫面摘要仍是 X 的檔名與日期、X 的徽章仍在、且顯示錯誤訊息——① 空檔 ② 無藥名欄 ③ 5 MB＋1 byte ④ 20,001 列 ⑤ 表頭正確但所有列皆無藥名 ⑥ **解析成功但儲存層寫入失敗**（注入）⑦ `.xls` 檔 ⑧ 加密的 Office 檔 ⑨ **前段有效、後段截斷**的 XLSX。另：恰好 5 MB、恰好 20,000 列必須成功

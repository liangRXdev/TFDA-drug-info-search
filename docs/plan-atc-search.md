# 規劃：ATC 碼搜尋

- 修訂：v1（2026-10-20）
- 狀態：需求確認完成（依全域規則 §8 逐題確認），已實作

## 需求摘要（已定案）

| # | 項目 | 決策 |
|---|---|---|
| Q1 | 臨床目標 | 同時支援兩種用途：找同類藥（`C09` 列出 RAS 類、`C09CA` 列出 ARB），以及精確查詢（`C09CA01`）。採**開頭相符**比對 |
| Q2 | 觸發方式 | 搜尋範圍新增「**ATC**」按鈕（品名／成分／ATC／全部）。在品名或成分範圍下，輸入像 ATC 碼的字串時，建議清單出現「🏷️ 以 ATC 搜尋」，點選後才切換範圍，不靜默改變結果集。「全部」範圍**不**併入 ATC：`C09` 這類短字串混在品名或成分結果裡，會難以解讀 |
| Q3 | 失敗情境 | ① 結果上方**固定**說明「ATC 碼來自健保署資料，僅涵蓋健保品項」。② 健保只登載到較上層的品項（例如只到 `C09CA`）**不列入**更深一層的查詢（`C09CA01`），只顯示提示與筆數，因為列入就可能誤配到同類別的其他藥。③ 同一張許可證的**所有健保代號** ATC 都納入比對 |
| Q4 | 大類別呈現 | 卡片上限 30 筆不變。ATC 範圍下，卡片上方加上「**ATC 分組摘要表**」，欄位為代碼、成分、品項數；點某一列只顯示該組，再點一次取消。計數依目前的篩選（健保／劑型）計算，加總等於總筆數 |
| Q5 | 輸入驗證 | 轉成半形（NFKC）、去除空白、轉大寫。合法長度只有 1／3／4／5／7 碼（`^[A-Z](\d{2}([A-Z]([A-Z](\d{2})?)?)?)?$`），1 碼的解剖大類也允許。格式不符時**不搜尋**，顯示格式範例；格式正確但查無時，顯示「查無」與涵蓋範圍說明。建議清單只在 ≥3 碼且有命中時出現 |
| Q6 | 驗收 | `tests/atc.spec.mjs`（jsdom）＋人工檢視畫面（桌面、390px） |

## 資料事實（2026-10-20 實測）

- 22,245 筆中，只有健保品項 10,085 筆有 ATC；非健保品項約 55%，用 ATC 搜不到
- 428 筆的 ATC 不是完整 7 碼，最常見的是 `R05X`、`B05XC`、`N07CA`、`V03AX`、`A02AG`
- 56 張許可證對應到多個不同的 ATC

## 實作要點

- `app.js`：
  - `normalizeAtc`、`isAtcPrefix`
  - `drugAtcCodes`：合併主要代號與所有健保代號的 ATC，在建索引時算一次
  - `atcMatches`、`atcOnlyBroader`
  - `atcGroupOf`：決定品項歸入哪一列。優先歸到主要代號，否則取字典序第一個，確保每個品項只算一次
  - `buildAtcPanel`
  - `stripParens`：處理巢狀括號，例如 `TAK-491 (AZILSARTAN MEDOXOMIL (AS POTASSIUM SALT))`
- 篩選改變後，原本選定的代碼可能已經沒有品項，這時自動回到「全部」
- `index.html`：新增 ATC 範圍鈕與樣式（沿用既有 token）。摘要表採固定欄寬，避免手機上長成分名把品項數欄擠出畫面
- `sw.js`：`STATIC_CACHE` 升到 v9

## 驗證

- `tests/atc.spec.mjs`，涵蓋：
  - 比對：開頭相符、主要與次要代號、正規化、合法與不合法格式、查無
  - 「全部」範圍不用 ATC 比對
  - 摘要表：計數加總、點選縮小與取消、篩選連動、選定代碼失效時重設
  - XSS、巢狀括號
  - 建議清單的出現條件與範圍切換
- 變異測試 8 項，全數被抓到：
  1. 上層代碼被列入
  2. 只比對主要代號
  3. 拿掉格式驗證
  4. 拿掉正規化
  5. 篩選後不重設選定代碼
  6. 建議清單不限 3 碼
  7. ATC 範圍仍給藥名建議
  8. 拿掉涵蓋範圍說明
- 真實資料檢視：
  - `C09CA` 102 筆分成 7 組
  - `C09` 242 筆分成 31 組
  - `N07CA02` 出現「另有 35 筆只登載到 N07CA」的提示
  - 桌面與 390px 寬度都沒有水平捲動
